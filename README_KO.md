# Centum 100일 여정 다이어리 v3.0.0

휴대폰 설치와 로컬 저장을 우선한 PWA(Progressive Web App) 버전입니다.

## 핵심 구조

- **프로그램 파일:** HTTPS 웹 서버와 서비스 워커 캐시에 저장됩니다.
- **일기 데이터:** 휴대폰 브라우저의 IndexedDB에 저장됩니다.
- **업데이트:** 새 프로그램 캐시만 교체하며 IndexedDB 데이터는 유지합니다.
- **서버 전송:** 기본 프로그램에는 일기, 사진, PIN을 서버로 보내는 기능이 없습니다.
- **사진:** 최대 1440px JPEG로 압축한 뒤 휴대폰에 저장합니다.
- **PIN:** 평문이 아니라 Salt + SHA-256 해시로 저장합니다. 단, 4자리 PIN은 강력한 암호화 금고가 아니라 간단한 화면 보호 기능입니다.

## 휴대폰 설치

### Android / Chrome

1. 이 폴더를 HTTPS 주소에 배포합니다.
2. Chrome에서 해당 주소를 엽니다.
3. 브라우저 메뉴에서 **앱 설치** 또는 **홈 화면에 추가**를 선택합니다.
4. 앱의 설정 화면에서 **저장 데이터 보호 요청**을 누릅니다.
5. 첫 기록을 작성한 뒤 **백업 파일 내보내기**를 실행해 Google Drive 등에 보관합니다.

### iPhone / Safari

1. Safari에서 HTTPS 주소를 엽니다.
2. 하단의 **공유** 버튼을 누릅니다.
3. **홈 화면에 추가**를 선택합니다.
4. 홈 화면의 아이콘으로 앱을 실행합니다.
5. 정기적으로 백업 파일을 iCloud Drive에 저장합니다.

## 업데이트 방법

1. 새 버전의 파일을 **기존과 동일한 도메인 및 동일한 경로**에 덮어씁니다.
2. `sw.js` 안의 `APP_VERSION`과 `version.json`, `index.html`의 `CENTUM_VERSION`을 같은 값으로 올립니다.
3. 사용자가 앱을 열면 새 서비스 워커가 설치됩니다.
4. 화면 상단에 업데이트 안내가 나타나면 **지금 업데이트**를 누릅니다.
5. 앱 코드만 갱신되고 IndexedDB의 일기 데이터는 유지됩니다.

> 도메인 또는 설치 경로가 바뀌면 브라우저는 다른 앱으로 인식합니다. 기존 기록을 자동으로 찾지 못하므로 이동 전 JSON 백업이 반드시 필요합니다.

## 권장 배포 방식

정적 파일 호스팅이면 충분합니다.

- Cloudflare Pages
- GitHub Pages
- Netlify
- Firebase Hosting
- 개인 HTTPS 웹 서버

Cloudflare Pages 또는 Netlify에서는 포함된 `_headers` 파일이 서비스 워커의 최신 버전 확인을 돕습니다.

## 로컬 테스트

PC에서 압축을 해제한 폴더로 이동한 뒤 다음 명령을 실행합니다.

```bash
python -m http.server 8080
```

브라우저에서 `http://localhost:8080`을 엽니다. `localhost`는 서비스 워커 테스트가 허용되는 안전한 개발 주소입니다.

## 데이터 안전 수칙

- 브라우저 데이터 삭제, 앱 제거, 휴대폰 초기화 시 로컬 기록이 삭제될 수 있습니다.
- **휴대폰 내부 복구 지점**은 같은 브라우저 저장소 안에 있으므로 휴대폰 분실이나 전체 데이터 삭제에는 대비하지 못합니다.
- JSON 백업 파일은 암호화되지 않았으며 사진과 일기 전문을 포함합니다. 잠금된 개인 저장소에 보관하세요.
- 한 달에 한 번 이상 외부 백업을 권장합니다.
- 브라우저의 시크릿 모드에서는 사용하지 마세요.

## PWA의 알림 제한

서버 푸시나 네이티브 앱 기능 없이 순수 PWA만 사용하는 경우, 앱이 완전히 닫힌 상태에서 매일 정확한 시각에 로컬 알림을 보장할 수 없습니다. 이 버전의 알림은 지정 시각 이후 앱을 열었을 때 오늘 기록이 없으면 안내하는 방식입니다.

정확한 예약 알림, 생체 인증, 앱스토어 배포가 필요하면 다음 단계로 Capacitor 기반 Android/iOS 앱 포장을 권장합니다. 데이터 구조는 그대로 유지할 수 있지만 네이티브 저장소 마이그레이션 작업이 별도로 필요합니다.
